# team-brain — instructions for Claude

This repository is the team's long-term memory for running ~100 air-gapped OpenShift clusters
(bare metal via Metal3 + vSphere, HyperShift hosted control planes, GPU nodes, AKO load balancing).
When you work *in* this repo you are a librarian: keep it accurate, deduplicated, and safe.

See @README.md for the layout and @docs/FRONTMATTER.md for the required file header.

## Golden rules

- **Never commit to `main`.** Never write in `$TEAM_BRAIN_DIR` directly. Use
  `plugins/team-brain/scripts/brain-git.sh start <learn|curate|incident> <slug>`, which creates a
  worktree on `<kind>/<yyyy-mm-dd>-<slug>` and prints its path. Edit there, then
  `brain-git.sh submit <worktree> "<msg>"`. That runs index, then validate, then commit, push and
  `glab mr create`. `abort <worktree>` discards it.
- **Never write secrets** — tokens, pull secrets, kubeconfigs, passwords, certificates, BMC
  credentials, customer/project names that are classified. Replace with `<REDACTED>`.
  `python3 scripts/brain.py validate` only catches known patterns (private keys, pull-secret auth,
  kubeconfig `*-data`, `sha256~`/JWT/`glpat-`/AKIA tokens, `password=`). It does **not** catch BMC
  creds in prose, IPs, customer names or certs, so review those by hand.
  `# brain:allow-secret` at end of line suppresses a hit.
- **Search before you write.** `grep -ril <term> knowledge runbooks incidents inbox`. If a page
  already covers the topic, update it (and bump `last_verified`) instead of creating a new one.
- **Facts carry scope and confidence.** Every claim states versions/hardware it applies to and a
  `confidence` of `verified | observed | hypothesis`. Don't upgrade confidence without evidence.
- **Write version-generic.** The fleet is mixed (now OCP 4.16/4.20/4.22) and will move. State ranges
  ("since 4.18", "up to 4.20") in the body and in `applies_to`; never write "current version". Versions
  and ref rules live only in `knowledge/meta/fleet-versions.md` — add a row there, don't hard-code
  versions elsewhere. The pinned Kubernetes docs are 1.35 only; check feature state for older clusters.
- **Placeholders for locations.** Region, site, MCE and cluster names are classified: write `<region>`, `<site>`,
  `<mce>`, `<cluster>` (shape `ocp4-<env>-<name>-<site>`), never real ones, and no internal IPs/hostnames.
  Fleet shape: `knowledge/openshift/fleet-topology-hub-mce-hosted.md`.
- **Metrics:** one Grafana, one Prometheus datasource per cluster named `Moby / <cluster-name>`. Resolve
  the datasource UID first and pass it on every query (see `knowledge/observability/grafana-one-datasource-per-cluster-prometheus.md`).
- **Don't edit `docs/upstream/`** — it's a pinned mirror, regenerated by a script.
- **Don't edit `INDEX.md`** — regenerate with `python3 scripts/brain.py index`.

## Where things go

| You learned… | Put it in |
|---|---|
| A quirk, root cause, or behaviour of our environment | `knowledge/<area>/<topic>.md` |
| A repeatable procedure with commands | `runbooks/<area>/<task>.md` |
| What happened during an outage/degradation | `incidents/<yyyy>/<yyyy-mm-dd>-<slug>.md` |
| Something unsure / unsorted / needs a human to judge | `inbox/<yyyy-mm-dd>-<slug>.md` |
| A new or changed MCP server | `mcp/servers/<name>.md` + `plugins/team-brain/.mcp.json` |

Areas (create a new one only if nothing fits): `openshift`, `kubernetes`, `hypershift`,
`baremetal`, `vsphere`, `networking`, `storage`, `gpu`, `observability`, `registry-mirroring`,
`gitops`, `security`, `meta` (repo/tooling pages). An unknown area is only a validate *warning*;
when adding one, update `AREAS` in `scripts/brain.py` too.

## Curation (when asked to curate, or via /team-brain:brain-curate)

1. For each file in `inbox/`: decide promote / merge into existing page / discard (and say why).
2. Merge duplicates; keep the more specific scope; keep history in a `## History` section.
3. Flag pages with `last_verified` older than 180 days in the MR description; don't delete them.
4. Regenerate the index, validate, commit, push, open one MR summarising every decision.

## Commit messages

`brain(<area>): <what was learned>` — e.g. `brain(hypershift): nodepool stuck when CAPI pre-drain hook times out`.
Incidents use `incident(<area>): ...`.

## Gotchas

- Start new pages from `templates/{knowledge,runbook,incident}.md`. Incidents need extra frontmatter
  (`severity`, `status`, `clusters`, `started`). `inbox/` files must be `type: inbox` (folder determines type).
- Frontmatter parser is a flat YAML subset: no multiline or nested values; `tags`, `applies_to`, `owners` are `[lists]`.
- `python3 scripts/brain.py index --check` fails if INDEX.md is stale. There is no CI and no test suite,
  so `validate` is the only gate. The README's "CI rejects…" is not true yet.
- Empty dirs aren't tracked: a new area folder needs a file in it.
- Air-gapped: look things up with the team-knowledge MCP tools (`search`, `read`, `search_code`,
  `find_definition`, `read_code`), not web search.
- `mcp/sources.json` and `deploy/openshift/shared-sources.json` must be kept in sync. A new MCP server
  needs `mcp/servers/<name>.md` (`type: mcp`) and an entry in `plugins/team-brain/.mcp.json`.
- Changing hooks or skills: bump `version` in `plugins/team-brain/.claude-plugin/plugin.json` (see docs/ADMIN.md).
